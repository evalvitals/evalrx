    Analyzer Zoo & Model Registry

    Reference tables for every registered analyzer and model spec. Discover the same information at runtime via evalrx.list_specs() and evalrx.registry.analyzers (see Discovery).

    Analyzers

    Analyzers are grouped the way the code is: one section per subpackage of evalrx/analyzers/. Each analyzer is keyed by the capability it needs from the model, not by a black-box / white-box label.

    Uncertainty uncertainty/ 6 0
    Hallucination hallucination/ 5 2

    Geometry geometry/ 2 0
    Reasoning reasoning/ 7 0
    Agent agent/ 7 0
    Total 54 2

    How to read the columns:

    • Key: the registered name, as in evalrx.registry.analyzers.get(key).
    • Requires: capabilities the model must provide (Analyzer.requires). trajectories means the batch must carry agent trajectories (requires_trajectories). A dash means nothing is required of the model: the analyzer reads stored outputs, or re-runs cases through an injected runner or judge.
    • Modality: applies_to_modalities. It is matched by intersection with the model's modalities, so text covers every text-capable model, VLMs and omni models included. Bold slots must also be filled in the batch (requires_modalities); selection drops the analyzer when none of them is.
    • Status: ✓ = implemented; stub = registered, but _run raises NotImplementedError (Stage 2).

    Perturbation

    evalrx/analyzers/perturbation/: re-query the model on masked, ablated or rewritten inputs and measure what moves. Black-box (GENERATE / LOGPROBS), so these run on API models too; the cost is the number of extra model calls per case.

    Attribution

    evalrx/analyzers/attribution/: gradient-based saliency (GRADIENTS, a backward pass through a white-box model: hf_local keeps the autograd graph when asked with CaptureSpec(with_grad=True)). Both explain the next-token logit margin and map the result back onto the image's patch grid, with overlays on the case photo. Grad-CAM reads the decoder's image-token states rather than the vision tower.

    Analyzer Key Requires Modality Paper Status
    Grad-CAM gradcam GRADIENTS + LOGITS image + video Selvaraju et al. 2017 ✓
    Generic attention explainability generic_attention ATTENTION + GRADIENTS + LOGITS text + image Chefer et al. 2021 ✓

    Lens

    evalrx/analyzers/lens/: project intermediate hidden states through the unembedding (HIDDEN_STATES) to see at which layer a prediction forms, and where premature layers disagree with the final one; or project each attention head's own write, to see which heads write the answer. patchscope lets the model decode its own states instead: each layer's residual at the answer position (and optionally each image / audio token) is patched into a token-identity prompt at the same layer. On Qwen3.5-0.8B it reads the final answer about five layers earlier than the logit lens. embed_lens reads the media tokens where they ENTER the language model, through their nearest vocabulary embeddings: which carry image-specific words, which repeat across every image (recurring / high-norm, the sink- and dead-like tokens of Fan et al., inferred from the batch rather than from checkpoint-specific ids), and how close the image comes to each prompt word. On Qwen3.5-0.8B the input is not in vocabulary space (90% recurring, object grounding at chance); layer=0.9 reads the same lens deep, where 87% of image tokens are specific and the queried object is grounded (POPE AUROC 0.76).

    Analyzer Key Requires Modality Paper Status
    Logit lens logit_lens HIDDEN_STATES text + image nostalgebraist 2020 ✓
    Tuned lens tuned_lens HIDDEN_STATES text + image Belrose et al. 2023 ✓
    Layer contrast layer_contrast HIDDEN_STATES text + image Chuang et al. 2024; Wang et al. 2025 ✓
    Head logit attribution head_attribution HIDDEN_STATES + LOGITS text + image Elhage et al. 2021; Wang et al. 2023 ✓
    Patchscope patchscope HIDDEN_STATES + LOGITS text + image + audio + video Ghandeharioun et al. 2024 ✓

    Patching

    evalrx/analyzers/patching/: causal interventions. Write a clean run's activations into a corrupted run to localise where information is used (HIDDEN_STATES, read and write hooks), or cut attention edges and measure what the answer loses. These act on the live torch module of a local hf_local model through evalrx/analyzers/_internals/ (an attention function registered with transformers, and decoder-layer pre-hooks), and verify, once per model, that the edit-free path reproduces the native logits. Hybrid stacks (Qwen3.5, Qwen3-Next: softmax + gated-delta-rule linear attention) are edited on every layer: a linear layer's text positions get its output re-run on the sequence without the media tokens (_internals/linear_mix.py). Latent / unverified attention is refused. Qwen3.5 needs transformers 5 (the vllm35 environment), not the [local] extra.

    attribution_patching estimates causal_trace's patch for every single token at every layer from gradients (GRADIENTS), averaged along the corrupt → clean media path (EAP-IG). It reports single tokens only — the answer position, and the question / template token that relays the media's information — because the media tokens' joint patch is not additive and a sum of gradient estimates does not track it. Each case is checked against exact patches of the sites it reports, and only cases that pass enter the aggregates.

    path_patching asks which heads carry the media's effect DIRECTLY to the answer: one head's output under corrupted media, every other head (linear-attention value heads included) frozen at its clean output, MLPs recomputed. Heads are screened by direct logit attribution and the top top_k patched exactly; patching every head at once reproduces the whole effect at the answer position (a tested identity), so the shares are exact fractions of it.

    attention_temperature divides the text's pre-softmax scores on the media by a temperature while keeping each row's total media weight (scope="within"): the model looks at the image as much as before, only more sharply or more broadly — FOCUS, where attention_sensitivity changes the AMOUNT. Softmax layers only.

    Reasoning

    evalrx/analyzers/reasoning/: text-chain diagnostics, all black-box. Read the two hygiene probes first: answer_extraction_audit (is the FAIL label real, or did the grader miss the answer?) and termination_audit (did the generation stop cleanly, or hit the token budget or a repetition loop?). Both produce confounds that mimic every other probe's "bad" column. The rest decompose how a chain failed.

    Answer-extraction audit answer_extraction_audit — text + image Lightman et al. 2024 ✓
    Termination audit termination_audit GENERATE text + image Holtzman et al. 2020 ✓
    Arithmetic audit arith_audit — text + image Cobbe et al. 2021 ✓
    Self-repair self_repair GENERATE text + image Huang et al. 2024 ✓

    Agent

    evalrx/analyzers/agent/: read multi-step agent runs (Trajectory) rather than single turns. Ordered cheapest first: deterministic heuristics, then LLM judges, then probes that re-run the agent through an injected runner (counterfactual, reliability_probe, tool_shap). Trajectories are usually loaded from disk with model=None, which is why most of these require nothing of the model.

    Loop detect loop_detect trajectories text + image MAST, Cemri et al. 2025 ✓
    Ignored observation ignored_obs trajectories text + image MAST, Cemri et al. 2025 ✓

    Trajectory rubric trajectory_rubric trajectories text + image MAST, Cemri et al. 2025 ✓

    Model Registry

    From list_specs() (evalrx/specs.py). Modalities are derived from the components a spec declares (vision tower → image, audio tower → audio, video) and are what analyzer selection matches on. Traits come from the spec flags: MoE (is_moe), reasoning (is_reasoning), tool calling (tool_calling: the chat template renders tools, which grants TOOL_CALLS on the local backend) and JAX (also runnable on the jax_local backend).

    Keeping this page current

    The tables above are generated from the analyzer registry and evalrx/specs.py by tools/gen_analyzer_docs.py. After adding an analyzer or a model spec, run:

    python tools/gen_analyzer_docs.py           # add new rows, refresh the derived columns
python tools/gen_analyzer_docs.py --check   # exit 1 if the page is stale

    A new key gets a placeholder row in its section; fill in its name and Paper (or Notes) by hand. A new analyzers/ subpackage or model group needs its own heading and marker pair first. The test suite runs the same check (tests/test_analyzers/test_analyzer_docs.py).
